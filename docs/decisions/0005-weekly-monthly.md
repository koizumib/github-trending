# 0005 ウィークリーとマンスリーの Trending も取る

- 日付：2026-09-30
- 状態：決定（設計書 §10 の7「ウィークリーの Trending」への答え）

## 背景
本人から「GitHub の公式のように、weekly と monthly のトレンドも見たい」とのこと。

## 決定
- `prepare` が毎朝、`github.com/trending`、`?since=weekly`、`?since=monthly` の3ページを、同じクライアントで1秒以上空けて1回ずつ取る
- デイリーが読めないときは今までどおり失敗させる。ウィークリー・マンスリーが読めないときは警告だけ出して、その期間を飛ばす
- 保存は `data/weekly/YYYY-MM-DD.json`、`data/monthly/YYYY-MM-DD.json`。new / continuing の分類はデイリーだけ。増えたスターは `stars_period` という名前にする（「今日」ではないため）
- まだ要約がないものは要約の対象にする。順番は、デイリーの new → returning → 前の日に回された continuing → ウィークリー → マンスリー。同じリポジトリは1回だけ。`max_summaries_per_day` の上限はそのまま
- サイトは、上部のタブでデイリー・ウィークリー・マンスリーを切り替える。`/`、`/weekly/`、`/monthly/` が最新の日、`/d/日付/`、`/d/日付/weekly/`、`/d/日付/monthly/` が日ごと
- Discord の通知は、これまでどおりデイリーの分だけ（M5 で必要なら考え直す）

## 影響
- 始めた直後は、ウィークリー・マンスリーにしか出ていないものが30件ほど要約待ちになる。1日15件の上限なら数日で追いつく
- `CLAUDE.md` の原則2の「1日1回」を、「3ページを1日1回ずつ」に直した
