# 0006 他のエンジニアにも公開し、届け方は Discord を本命にする

- 日付：2026-09-30
- 状態：方向は決定。まず本人だけで試してから公開する

## 背景
本人から「他のエンジニアも見られる、ちょっとしたサービスのように展開したい。不特定多数がメルマガのように通知を受け取れるようにしたい」とのこと。メール、RSS、Discord を比べ、本人が Discord を本命に選んだ。

## 決定
- 段階0（M4〜M7）：まず1〜2週間は本人だけで使う。Discord は本人のサーバーのチャンネルに流す。要約の質と使用量を見て、よければ段階1に進む
- 段階1（公開するとき）：trending-digest 用の公開 Discord サーバーを作り、アナウンスチャンネルに Webhook で流す。受け取りたい人は招待リンクから参加する。仕組みは Webhook のままで、サーバーは要らない
- 他の人が自分のサーバーに取り込めるよう、アナウンスチャンネルのフォロー機能を使う。Webhook の投稿がフォロー先に自動で流れるかを、公開の前に確かめる。流れなければ、Actions から Discord の API で「公開」する方法を考える
- 段階2（必要になったら）：他の人のサーバーに招待できる Bot。設定のコマンドを受け付けるサーバー（Cloudflare Workers など）と、届け先を覚える場所が要り、静的ではなくなるので、段階1で足りないときだけ
- メールのニュースレターは今はやらない。やるなら購読者の管理を外部の配信サービスに任せ、メールアドレスをこちらで持たない
- 要約の公開は本人の判断で進める。サイトとメッセージには「要約は Claude Code が書いたもので、誤りを含むことがある」と書き、元のリポジトリへのリンクを必ず付ける

## 未決

- 個人のプランの routine で公開の配信を続けてよいか（利用規約。本人が確かめる）
