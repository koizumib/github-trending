# 0024 材料集めが終わったら Actions から routine を起動する（時刻の差に頼らない）

- 日付：2026-10-02
- 状態：決定（0007 の「6:00 に prepare、7:00 に routine」を置き換える）

## 背景
GitHub Actions の定期実行は、混み合うと大きく遅れる。実際に、6:00 の予定だった「取得と材料集め」は、10/1 は 9:18、10/2 は 9:25 に動いた（9:00 の見張りも 12:18 に動いた）。routine は 7:08 に時刻どおり動くので、10/2 は材料が前日のままで、手順書どおり30分待って止まった。本人から「時間差による実行停止が起きないようにしたい」とのこと。

routine を起動する方法は、決まった時刻・API・GitHub の出来事の3つ。GitHub の出来事は pull request とリリースだけで、push では起動できない。

## 決定
- 「取得と材料集め」（`prepare.yml`）が成功したら、最後の段階で routine の API（`/fire`）を呼んで起動する。URL は workflow に書き、トークンは GitHub の Secrets（`CLAUDE_ROUTINE_TOKEN`）に置く。トークンがなければ、警告を出してその段階を飛ばす
- routine の決まった時刻の起動（7:08）は外す。外さないと、材料集めのあとの起動と二重に動く
- 「取得と材料集め」の定期実行は、混みやすい「0分」を避け、5:47・7:17・8:47（日本時間）の3回にする。今日の分がすでに取れていれば、2回目以降は何もせず終わる（routine も起動しない）。手で動かしたとき（workflow_dispatch）は、いつでも動き、routine も起動する
- routine は、すでに要約がある項目は飛ばす（同じ日に二度起動されても、書き直さない）
- 6時より前は通知しない（0017）ので、材料集めが早く動いて要約が6時前に終わった日は、9時の見張りが通知を送る
